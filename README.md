# ghostgen — боевая генерация предметных фото на машинах Salad

Рецепт: Qwen-Image-2.1 SDNQ-4bit, turbo LoRA 1,0 + ghost LoRA 0,5, 6 шагов, 512 (`config.py`, `RECIPE_ID`).

## Схема

```
MAC (подготовка)
  submit.py: товары → входные фото в хранилище inputs/<pid>/<k>.jpg (sha256 каждого)
           → манифест пачки jobs/<chunk>.json (pid, промпт, сид, входы+sha256, рецепт) → Redis: пачка в очередь

REDIS (общая очередь с арендой пачек)
  pending ──claim──► leased (аренда 15 мин, машина продлевает каждую минуту)
     ▲                   │ машину сняли → аренда истекла → reap → пачка снова в pending
     └───────────────────┘ сделанные товары пачки второй раз не делаются (итог по товару в Redis)

МАШИНА (один контейнер, node.py держит три процесса)
  [1] fetcher   берёт пачку, качает входы, сверяет sha256 → work/inbox/<chunk>__<pid>/ (tmp-папка → rename), ≤48 впереди
  [2] generator только видеокарта; модель загружена один раз; эталонный замер на старте (медленная машина → IMDS reallocate);
                сверяет входы и аренду → work/out/<pid>.png (pid, пачка, рецепт, sha входов — внутри PNG) + <pid>.json
  [3] uploader  pid: имя = json = PNG = манифест; входы = манифест; sha PNG; размер; не пустая
                → outputs/<рецепт>/<pid>.png → перечитать и сверить → results/<рецепт>/<pid>.json → Redis: итог → удалить локально

MAC / СЕРВЕР (потом)
  db_apply.py: results/ → проверка объектов → пачками UPDATE "Product" (по умолчанию только отчёт)
```

## Что гарантируется

- **Не перепутать.** Id товара проверяется в пяти местах: имя папки/файла, job.json, текст внутри PNG, json результата, манифест пачки.
  Входы сверяются по sha256: при скачивании, перед генерацией и при выгрузке. Все файлы пишутся атомарно (временный файл → rename).
  Проверка: `tests/test_checks.py` — 7 видов подмены, все отвергаются.
- **Не потерять.** Картинка считается сделанной, только когда лежит в хранилище и сверена после загрузки. Итог пишется и в хранилище
  (results/), и в Redis. Машину сняли без предупреждения — её пачки вернутся в очередь, когда истечёт аренда (15 мин).
  Сделанное не повторяется. Штатная остановка (SIGTERM) — готовое выгружается, пачки возвращаются сразу.
  Проверка: `tests/test_e2e.py` — 60 товаров, машину A убивают SIGKILL посреди пачки, машина B доделывает; 59 успешных,
  1 намеренно испорченный вход отказан, цвет каждой картинки = цвет своего товара.
- **Не тормозить.** Скачивание и выгрузка — отдельные процессы на процессоре; генератор только генерирует, товары ждут его на диске.

## Запуск

Проверки (на Mac, из `looks_pipeline/services`; не из корня looks_pipeline — там `profile.py`):

    uv venv ghostgen/.venv --python 3.11 && uv pip install --python ghostgen/.venv/bin/python redis pillow numpy boto3
    ghostgen/.venv/bin/python -m ghostgen.tests.test_checks
    ghostgen/.venv/bin/python -m ghostgen.tests.test_e2e

Постановка и обзор:

    GG_REDIS_URL=... GG_S3_BUCKET=... python -m ghostgen.submit jobs.json --chunk 200
    python -m ghostgen.status [--reap] [--requeue-failed]
    python -m ghostgen.db_apply --url-prefix https://<cdn>/ [--apply]

Машина: образ по `Dockerfile`; команда по умолчанию `python -m ghostgen.node`.

Переменные группы контейнеров в Salad (секреты — только туда, не в образ):

| переменная | значение |
|---|---|
| `GG_REDIS_URL` | `rediss://:пароль@хост:порт/0` |
| `GG_S3_BUCKET`, `GG_S3_ENDPOINT`, `GG_S3_REGION` | хранилище |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | ключи хранилища (только запись в этот бакет) |
| `GG_MAX_STEP_SEC` | порог медленной машины, по умолчанию 0,45 |

## Открытые решения (за пользователем)

1. **Redis**, доступный из интернета с паролем и TLS: управляемый (например Upstash, Redis Cloud, Yandex Managed Redis) или свой сервер.
   Нагрузка крошечная — десятки операций в секунду.
2. **S3**: бакет и публичный адрес для ссылок (`--url-prefix`).
3. **Поле в базе**: по умолчанию `ghostImageUrl` + `ghostImageRecipe`; нужен доступ на запись (`GG_DATABASE_URL_RW`).
4. **Реестр образов**: куда класть образ (Docker Hub / GHCR, закрытый). Образ ~20 ГБ из-за модели внутри.
